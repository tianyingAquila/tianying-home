# GAME OS Implementation Plan

**Goal:** 完成卡带选择、插入、展开真实游戏和反向退出闭环。

**Architecture:** 在原页面之上建立轻量选择器；同一游戏 iframe 的真实棋盘 / Canvas 持续从预览演化为运行界面。桥接层只负责嵌入模式、生命周期和几何位置，规则继续由原游戏负责。

**Tech Stack:** 原生 HTML、CSS、JavaScript、Web Animations、同源 iframe。

**Spec:** `docs/superpowers/specs/2026-10-05-game-os-design.md`

用户指定一次执行完成，采用当前会话直接执行，不追加设计审批阶段。

## Global constraints

- 浅色背景、克制紫色、统一导航；不采用列表布局、3D 旋转或沉重依赖。
- 启动 1670ms；真实棋盘 / Canvas 节点不替换、不导航、不缩放。
- 不修改冻结引擎或游戏规则；退出保存本局。
- 先完成选择器结构和切换，再加入启动、退出、嵌入游戏。

## Review focus

1. 快速重复点击和动画中 resize：不会启动两次或卡在中间状态。
2. 本局状态在退出和重新进入后仍保留；扫雷计时和塔防时间不会算入选择页停留时间。
3. 改变雷区尺寸、地图、滚动位置后退出：新棋盘仍正确缩入卡带。
4. iframe 内焦点、键盘、结算弹窗与可见控制不会被预览触发层拦截。
5. 低高度 / 窄屏和减少动态效果：不产生不可达按钮或无限等待。
