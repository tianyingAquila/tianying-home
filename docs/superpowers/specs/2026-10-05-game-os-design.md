# GAME OS design

用户已提供完整设计要求，并明确授权常规设计选择、一次执行完成。

按用户第二次草图重构体量：中央大卡带占据主要视口，另一张同体量卡带被右侧屏幕边缘裁切；宽幅工业设备底座固定贴住视口底部，中央插槽与主卡对齐。整个选择页严格一屏，无横向或纵向滚动。切换只有平移和透明度，不缩放游戏画面。保留既有系统字体、#f2f0ec 奶白、#14161a 墨黑、#e7e4df 机身灰、#7060a8 状态紫及网站信息。预览材质按用户的“微波炉观察窗”比喻，采用浅内陷座、透明面板细厚边和一宽一窄的环境反光；全部使用 CSS 覆盖层，不改棋盘几何、不使用模糊滤镜。hover 卡带上浮 8px，反光平移 16px；启动时材质和窗框阴影退去。

每个卡带读取对应原游戏页面，添加同源 base 后挂载到 iframe srcdoc；保留服务器禁止直接页面嵌入的原有响应头。预览与运行使用同一个已布局文档、同尺寸真实 DOM 棋盘或 Canvas，中央裁切允许，只平移、绝不缩放。启动不换文档、不替换棋盘：320ms 下插 30px，900ms 棋盘平移且外壳/薄膜退去，450ms 周围 UI 显现，共 1670ms。只有最后一步才恢复游戏输入。游戏的内部滚动可用，外层页面仍然锁定。退出先隐藏 UI，再反向平移回卡带，保留游戏实例和进度。选择器期间输入被触发层、pointer-events 和 inert 隔离，暂停塔防推进、暂停扫雷计时；运行时恢复。不更改冻结塔防版本或规则。

用 query 参数隔离嵌入样式，独立游戏页继续正常访问。原生 CSS / Web Animations，无新增依赖。按 2026-10-06 用户要求，核心卡带运动和 UI 显现始终保留动画；不让系统减少动态效果设置将启动和切换变成瞬间跳转。几何测量表面不得附加 CSS transform transition，内部滚动条固定占位；原游戏文档挂载时验证缓存以取得最新嵌入样式。至少验证 1440、1280、1024 桌面宽度，并检查窄屏。验证真实开格、插旗、提示、配置、建造、开波、暂停、地图选择以及退出后恢复；检查棋盘 / Canvas 节点身份和页面 URL 在启动前后保持一致。执行全套 Node 回归、冻结版本验证和 diff 检查；更新 README。
